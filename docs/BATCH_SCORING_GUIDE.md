# 批量审核使用指南

## 概述

批量审核功能允许您对整个目录树中的所有文档进行智能评分，系统会自动：
- 递归扫描输入目录，识别所有支持的文档文件（PDF、DOCX、DOC）
- 保持输入输出目录结构一致
- 为每个文档生成独立的JSON和HTML评分报告
- 生成总体和分层级的汇总报告

## 快速开始

### 基本用法

```bash
python run_batch_rag_scoring.py <输入目录> [输出目录]
```

### 示例

```bash
# 使用默认输出目录
python run_batch_rag_scoring.py /path/to/documents

# 指定输出目录
python run_batch_rag_scoring.py /path/to/documents output/my_results
```

## 功能特性

### 1. 递归目录扫描
- 自动识别所有子目录中的文档文件
- 支持任意深度的目录层级
- 支持的文件格式：`.pdf`、`.docx`、`.doc`

### 2. 目录结构映射
- 输出目录完全保持输入目录结构
- 每个文档的报告存放在对应的子目录中
- 便于按照原始组织结构查看结果

### 3. 多格式报告
- **单文档报告**：每个文档生成JSON和HTML两种格式的详细评分报告
- **汇总报告**：生成JSON、TXT、HTML三种格式的批量汇总报告

### 4. 分层级统计
- **总体统计**：所有文档的综合统计信息
- **子目录统计**：每个子文件夹的独立统计分析
- **评分分布**：分数段分布、等级分布
- **处理详情**：成功/失败清单、耗时分析

## 汇总报告内容

### 总体统计
- 总文件数
- 成功处理数
- 处理失败数
- 成功率
- 平均分数
- 最高/最低分数
- 中位数

### 子目录统计
对每个子目录分别统计：
- 文件数量
- 成功/失败数
- 平均分数
- 成功率

### 评分分布
- **分数段分布**：90-100、80-89、70-79、60-69、0-59
- **等级分布**：优秀、良好、中等、及格、不及格

### 处理耗时分析
- 总耗时
- 平均耗时
- 最快/最慢处理时间
- 快速/正常/慢速处理数量

### 失败分析
- 失败总数
- 错误类型统计
- 失败文件清单

## 前置条件

### 1. VLLM服务
确保VLLM服务已启动并运行：

```bash
# 启动VLLM服务（在另一个终端中）
bash scripts/start_vllm.sh
```

默认服务地址：`http://localhost:8000/v1`

### 2. RAG知识库
确保已建立RAG知识库：

```bash
# 建立或更新知识库
python quick_reindex.py
```

## 使用步骤

### 步骤 1：准备文档
将待评分的文档组织到目录中，可以使用任意层级的子目录结构。

### 步骤 2：启动VLLM服务
```bash
bash scripts/start_vllm.sh
```

### 步骤 3：运行批量评分
```bash
python run_batch_rag_scoring.py /path/to/your/documents
```

### 步骤 4：查看结果
- 查看控制台输出的统计摘要
- 打开输出目录中的HTML汇总报告
- 浏览各个文档的详细评分报告

## 查看汇总报告

### HTML汇总报告（推荐）
打开 `output/batch_rag_scoring/batch_summary_YYYYMMDD_HHMMSS.html`

HTML报告包含：
- 美观的数据可视化图表
- 交互式统计信息
- 清晰的分层级统计
- 详细的失败分析（如有）

### 文本汇总报告
打开 `output/batch_rag_scoring/batch_summary_YYYYMMDD_HHMMSS.txt`

适合快速查看或终端显示。

### JSON汇总报告
打开 `output/batch_rag_scoring/batch_summary_YYYYMMDD_HHMMSS.json`

适合程序化处理或进一步分析。

## 注意事项

### 1. 处理时间
- 每个文档的评分通常需要 30-60 秒
- 批量处理大量文档可能需要较长时间
- 建议在处理大批量文档时合理安排时间

### 2. 资源消耗
- VLLM服务需要较大的GPU/CPU资源
- 确保系统有足够的内存和存储空间
- 建议逐批次处理大量文档

### 3. 错误处理
- 单个文档失败不会影响其他文档的处理
- 失败文档的错误信息会记录在汇总报告中
- 可以针对失败文档单独重新处理

### 4. 文件命名
- 报告文件名包含时间戳，避免覆盖
- 建议保持原始文档文件名清晰易读
- 避免使用特殊字符或过长的文件名

## 故障排除

### 问题：VLLM连接失败
**解决方案**：
```bash
# 检查VLLM服务是否运行
curl http://localhost:8000/v1/models

# 如未运行，启动服务
bash scripts/start_vllm.sh
```

### 问题：知识库为空
**解决方案**：
```bash
# 重新建立知识库
python quick_reindex.py
```

### 问题：某些文档处理失败
**解决方案**：
1. 查看汇总报告中的失败分析
2. 检查失败文档的格式是否正确
3. 查看日志文件了解详细错误信息
4. 针对失败文档单独使用 `run_complete_rag_scoring.py` 处理

### 问题：处理速度太慢
**解决方案**：
1. 检查VLLM服务配置，确保使用GPU加速
2. 减少每批次处理的文档数量
3. 优化服务器资源配置

## 高级用法

### 只处理特定类型的文档
可以在运行前将不需要的文档移出目录，或使用符号链接组织需要处理的文档。

### 自定义输出位置
```bash
# 指定自定义输出目录
python run_batch_rag_scoring.py /input/docs /custom/output/path
```

### 查看处理日志
详细的处理日志保存在：
```
logs/batch_rag_scoring_YYYYMMDD_HHMMSS.log
```

## 与单文档评分的区别

| 特性 | 单文档评分 | 批量审核 |
|------|-----------|---------|
| 命令 | `run_complete_rag_scoring.py` | `run_batch_rag_scoring.py` |
| 输入 | 单个文件路径 | 目录路径 |
| 输出结构 | 单一目录 | 保持输入目录结构 |
| 汇总报告 | 无 | 有（JSON/TXT/HTML） |
| 进度跟踪 | 单个文档详情 | 批量进度统计 |
| 适用场景 | 测试、调试、单独评分 | 生产环境、大批量处理 |
